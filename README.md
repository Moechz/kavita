# Kavita for TerraMaster TOS 7

[Kavita](https://github.com/Kareadita/Kavita) — a self-hosted digital library
server for comics, manga, books and magazines (blazing-fast web reader +
management UI) — packaged as a native deb for the TerraMaster **TOS 7 App
Center**.

## Download & install

Grab the package for your NAS architecture from
[Releases](https://github.com/Moechz/kavita/releases):

| Asset | Architecture |
|---|---|
| `kavita_<version>_amd64.deb` | x86_64 NAS |
| `kavita_<version>_arm64.deb` | ARM64 (aarch64) NAS |

Each package ships with its own `.sha256` checksum file.

Install via **App Center → Manual Install** (upload the `.deb`), or on the
command line:

```sh
sha256sum -c kavita_<version>_amd64.deb.sha256
sudo apt install ./kavita_<version>_amd64.deb
```

After installing, open the app from the TOS desktop (it opens in a new browser
tab at `/kavita/`) and complete the first-run wizard to create the admin
account, then add your library folders.

## What this package does

- **New-tab (External Open) integration**: the desktop icon opens
  `http(s)://<nas>:<port>/kavita/` through the platform web server. No extra
  port is exposed.
- **Loopback only**: the backend listens on `127.0.0.1:8500`, so all traffic
  goes through the TOS web server route.
- **Native sub-path support**: the app runs under `BaseUrl=/kavita/`
  (upstream `UsePathBase` + SPA `<base href>`), so the reader, REST API,
  SignalR (WebSocket) and OPDS feeds all work behind the prefix.
- **State on the data volume**: the runtime tree lives in
  `/usr/local/kavita/bin`, with `bin/config` symlinked to `/var/lib/kavita`
  (database, covers, cache, logs). `apt remove` keeps your data;
  `apt purge` deletes it. Source media files are never touched.
- **Hardened service**: dedicated unprivileged `kavita` user, systemd sandbox
  (`NoNewPrivileges`, `ProtectSystem=strict`, `ProtectHome`, explicit
  `ReadWritePaths`).
- **First-run setup**: the web UI has no default password — the first visitor
  creates the admin account. The JWT signing key is generated by the
  application on first start.
- **Privacy**: a bilingual privacy policy ships with the package
  (`/kavita/privacy-policy.html`). The package publisher collects no data;
  the upstream anonymous usage statistics can be disabled in
  *Server Settings → Analytics*.

## Binary provenance (auditability)

The deb does **not** ship the upstream prebuilt release artifacts. All
binaries are built from the upstream source tag by public CI, so that every
executable in the package can be audited:

| Step | Evidence |
|---|---|
| Upstream source | `Kareadita/Kavita` tag `v0.9.1.4` (commit recorded in `BUILD-INFO`) |
| Build recipe | [`.github/workflows/build-upstream.yml`](.github/workflows/build-upstream.yml) — mirrors the upstream release build (Node 24 WebUI build + `monorepo-build.sh` dotnet publish) |
| CI logs | public GitHub Actions run (run id recorded in `BUILD-INFO`) |
| Hash pinning | the CI release publishes `SHA256SUMS`; `config.env` pins the same sha256 independently (double verification) |
| In-package markers | `/usr/local/kavita/bin/BUILD-INFO` and `/usr/local/kavita/PROVENANCE.md` |

## Building the deb yourself

```sh
make check          # asset / syntax self-checks (no network)
./build.sh          # amd64: fetch -> stage -> verify -> deb
TARGET_ARCH=arm64 ./build.sh
./build.sh info     # current version / arch / artifact paths
```

`fetch` downloads the source-built runtime tarball from the CI release and
verifies it against both the release checksum list and the sha256 pins in
`config.env`; `stage` assembles the `/usr/local/kavita` tree; `verify` asserts
the platform requirements (layout, config.ini, languages, systemd unit, nginx,
loopback hardening, ELF architecture, provenance markers); `deb` produces
`out/kavita_<version>_<arch>.deb` plus its `.sha256`.
